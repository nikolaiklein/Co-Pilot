# Project Conventions

Accepted patterns and enforced conventions from council reviews. The council reads this file before every review to avoid re-flagging resolved decisions.

---

## Enforced Conventions

These must be followed — flag violations as findings.

### EC-1: Webhook secret token validation
**Convention:** All webhook endpoints must validate the `X-Telegram-Bot-Api-Secret-Token` header. Reject requests with missing/wrong tokens with 403.
**Origin:** Hunt — Council Review 2026-03-14-2238
**Principle:** `references/security.md` → Principle 7

### EC-2: Cron/debug endpoint authentication
**Convention:** All `/cron/*` and `/debug/*` endpoints must be protected by shared secret header check or IAM. No unauthenticated access to internal endpoints.
**Origin:** Hunt — Council Review 2026-03-14-2238
**Principle:** `references/security.md` → Principle 7

### EC-3: .dockerignore required
**Convention:** Project must have a `.dockerignore` excluding `.env*`, `.git/`, `__pycache__/`, `.council/`, `*.md`, `.venv/`.
**Origin:** Docker/Deploy Expert — Council Review 2026-03-14-2238
**Principle:** Docker best practices — container security

### EC-4: LLM call logging mandatory
**Convention:** All LLM calls across all providers must log model, token usage, latency, and finish_reason. No provider may silently swallow call metadata.
**Origin:** Willison — Council Review 2026-03-14-2238
**Principle:** `references/quality-llm.md` → Principle 4

### EC-5: Destructive commands require confirmation
**Convention:** Destructive commands (`/correct`, `/clear`, and any future data-modifying commands) must show a confirmation step with inline keyboard before executing. No single-command irreversible actions.
**Origin:** Friedman — Council Review 2026-03-14-2238
**Principle:** `references/quality-ux.md` → Principle 8

### EC-6: Webhook must return proper HTTP status codes
**Convention:** Webhook endpoint must return HTTP 500 for transient errors so Telegram retries. Never return 200 with error payload.
**Origin:** Backend/Python Expert — Council Review 2026-03-14-2238
**Principle:** `references/quality-backend.md` → Principle 3

### EC-7: DB write failures must propagate
**Convention:** Database write failures (`save_message`, `update_user`, `save_report`) must propagate exceptions to callers, not silently `pass`. Callers must inform the user of failure.
**Origin:** Backend/Python Expert — Council Review 2026-03-14-2238
**Principle:** `references/quality-backend.md` → Principle 1

### EC-8: No internal details in error responses
**Convention:** Error responses (HTTP and Telegram) must never contain `str(e)` or raw exception text. Use generic error messages in all user/client-facing responses. Log full exceptions server-side only.
**Origin:** Hunt — Council Review 2026-03-14-2238
**Principle:** `references/security.md` → Principle 9

### EC-9: LLM-generated JSON must be schema-validated before Firestore write
**Convention:** Any JSON generated by LLM (analyzer profile, /correct output, any future structured output) must be validated against expected schema (required keys, correct types) before writing to Firestore. On validation failure, preserve existing data unchanged and log the error.
**Origin:** Willison — Council Review 2026-03-15-0020
**Principle:** `references/quality-llm.md` → Principle 1

### EC-10: Multi-document Firestore writes must use transactions
**Convention:** Any operation that writes to multiple documents or performs check-then-act (read count → check limit → write document → update count) must use a Firestore transaction. No sequential writes outside transactions for related data.
**Origin:** Leach — Council Review 2026-03-15-0020
**Principle:** `references/quality-postgres.md` → Principle 2

### EC-11: Error HTTP responses must use proper status codes
**Convention:** All endpoints must return appropriate HTTP status codes for errors: 503 for service unavailable, 500 for internal errors, 403 for auth failures. Never return HTTP 200 with `{"status": "error"}` payload.
**Origin:** Backend/Python Expert — Council Review 2026-03-15-0020
**Principle:** `references/quality-backend.md` → Principle 3

### EC-12: Never log user content — only metadata
**Convention:** Logs must never contain user message text, voice transcriptions, or uploaded file contents. Log only metadata: user ID, message length, file type, processing duration. User IDs in allowed-user lists must also be redacted (log count only).
**Origin:** Hunt — Council Review 2026-03-15-0020
**Principle:** `references/security.md` → Principle 3

### EC-13: Dockerfile must use non-root USER
**Convention:** Dockerfile must create a non-root user and switch to it via USER directive before CMD. Application must never run as root inside the container.
**Origin:** Docker/Deploy Expert — Council Review 2026-03-15-0020
**Principle:** Container security — least privilege

### EC-14: All LLM analyze() calls must include structured logging
**Convention:** All `analyze()` methods on all providers must log the same structured metadata as `generate()`: model identifier, token usage, latency, finish_reason. No LLM call may execute without observability.
**Origin:** Willison — Council Review 2026-03-15-0020
**Principle:** `references/quality-llm.md` → Principle 4

### EC-15: asyncio.create_task must use _fire_and_forget with GC protection
**Convention:** All fire-and-forget background tasks must use the `_fire_and_forget` helper (or equivalent) that: (1) stores a strong reference in a module-level set, (2) adds a `done_callback` that logs exceptions and removes the task from the set. Bare `asyncio.create_task()` without a stored reference is forbidden — the GC may silently discard the task before it completes.
**Origin:** Backend/Python Expert — Council Review 2026-04-03-2346
**Principle:** `references/quality-backend.md` → Principle 1

## Accepted Patterns

These patterns are intentional — do **not** flag as findings.

### AP-1: /cron/* endpoints return HTTP 202 immediately
**Pattern:** Cron endpoints return `{"status": "accepted"}` with HTTP 202 before the background work completes. This is required because Cloud Scheduler has a fixed request timeout and does not wait for long-running batch operations.
**Origin:** Docker/Deploy Expert — Council Review 2026-04-03-2346
**Note:** The fire-and-forget task itself must still use EC-15 (_fire_and_forget with GC protection).
